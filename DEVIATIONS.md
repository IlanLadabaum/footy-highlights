## Deviations

- **X1. Pre-round tables are computed locally from the season's results, not fetched from football-data's standings endpoint.** Finding (2026-10-11): `standings?season=…&date=…` silently ignores `date` and returns the *final/current* table — a spoiler trap like the `matchday` one. `matchday=` works but means one request per round. The app already downloads every season result (one request per competition), so it builds the table from "results with kickoff before the round's earliest kickoff" — the plan's back-calculation path — with zero extra requests. Verified: Premier League 2025-26 before matchday 11 matches football-data's official matchday-10 table exactly (unit test). No standings are cached because none are fetched (the "standings cache" in the M1 bullet is unused). The only standings request is the current table, used solely for deduction detection (see D12).
- **X2. "Before the round" uses the round's main block of dates, not its single earliest kickoff.** The plan defines the pre-round table as "matches with kickoff before the earliest kickoff of round N". Real data breaks that: Premier League 2025-26 Matchweek 31 had one game brought forward to February and one postponed to May, so "earliest kickoff" would have shown a February table. The app now uses the earliest kickoff within 4 days of the round's median kickoff, for the table cut-off, the round's date label and round ordering. A match brought forward is already counted in that table, and its row says so ("Played earlier than the rest of the round, so it's already in the table"). Postponed matches after the round can still be revealed and applied.

## Decisions

### M0 — Project setup
- **D1. Xcode project committed, generated by XcodeGen.** `project.yml` is the source; the generated `.xcodeproj` is also committed so contributors don't need XcodeGen.
- **D2. Non-UI code lives in a local Swift package `FootyKit`** (plus a `footy-cli` executable for live-data checks). The app target is a thin SwiftUI layer.
- **D3. No App Sandbox, no hardened runtime, ad-hoc signing ("Sign to Run Locally").** The app is distributed as an unsigned DMG (decided), so the sandbox brings nothing, and without it Debug builds can read `.env` from the project folder. Revisit if it's ever shipped via the App Store.
- **D4. The app target is "multiplatform" via `supportedDestinations: [macOS]`.** Adding iPad later is a one-line change plus `#if os(macOS)` cleanup.

### M1 — Data layer
- **D5. Title rules live in `competitions.json`** as per-channel regexes (`home`/`away`/`label` groups) plus a per-competition label regex for shared channels (CBS → UCL / Serie A / Carabao). Built from ~4,000 real 2025-26 titles; ≥98% of standard-format titles parse and ≥95% of parsed highlights match their fixture in every competition (tests).
- **D6. Excluded from the highlight filter:** beIN `RESUMEN` (Spanish-language duplicates), CBS UCL qualifiers, NBC Netbusters/compilations/full matches, ESPN FC non-"LALIGA Highlights" uploads.
- **D7. ESPN FC teaser prefixes** are stripped when parsing team names (text up to the last emoji, or a leading run of ALL-CAPS words). The whole ESPN FC source carries the "may show spoiler at start" flag, as decided.
- **D8. Matching window:** a video matches fixtures that kicked off between 1 h after and 5 days before it was published. If both names don't match, a single strongly recognised team that plays only once in that window is accepted. Team aliases (Wolves, Spurs, FC Cologne, PSG…) are in the config.
- **D9. Display names** are football-data short names with readability overrides in config (e.g. "Nottingham" → "Nottingham Forest", "Barça" → "Barcelona", "Atleti" → "Atlético Madrid").
- **D10. Round names:** "Matchweek N" for the Premier League (as in the plan's example), "Matchday N" for other leagues, "League Phase MD N" / "Round of 16 · 1st leg" etc. for the UCL.
- **D11. Rounds listed** are those where at least one match has kicked off (or has a highlight). Upcoming fixtures inside a listed round show their kickoff time; live ones show "In progress".
- **D12. Point deductions [pending your answer]:** the app fetches the current table once a day per league (never shown) and infers deductions as `3W + D − points`. Because the API gives no date for a deduction, pre-round tables **don't subtract it**; instead the table shows a footnote naming teams with a deduction this season. (Code supports subtracting; one-line change if you choose "apply".)
- **D13. "Highlights not available yet"** for a finished match less than 36 h old with no video, instead of "No highlights available", since uploads lag kickoff by hours.
- **D14. Without fixture data, the round comes from the title when the channel includes one** (CBS: "League Phase MD 1", "Third Round"); otherwise Fri–Mon "Weekend of …" / Tue–Thu "Midweek of …" windows in the user's time zone. This applies to the Carabao Cup always.
- **D16. Refresh details:** football-data season fetch per competition at most daily, or sooner (≥15 min) when a fixture that should be over isn't final yet; YouTube scan back to 1 Aug of the season's start year on first run, then incremental from the newest seen upload minus 2 days; a full rescan every 25 days and deletion of anything not seen for 30 days (ToS DP III.E.4.c). Only titles that parse as highlights are stored. First full refresh measured live: ~111 YouTube units, 11 football-data requests, ~30 s.
- **D17. Debug builds read `.env` *before* the Keychain.** Ad-hoc-signed rebuilds change the code signature, so Keychain reads could prompt on every rebuild. Release builds use only the Keychain. Settings says when a key comes from `.env`.

### M2 — Navigation screens
- **D18. Match rows show "Home v Away"** with date, video length, channel ("NBC Sports on YouTube") and state lines. The full neutral title (teams + competition + round) is the player screen's heading, since the round screen's title already names the competition and round.
- **D19. Mark all as watched:** the competition-wide action asks for confirmation; every mark-all also shows an 8-second "Undo" banner and registers with Edit → Undo (⌘Z). Mark-all only touches matches that have a playable highlight.
- **D20. The watched checkbox appears only on rows with a playable highlight.** The reveal checkbox ("Show score & update table", or "Show score" on full-width rounds) appears on every finished match with a score, including ones without highlights.
- **D21. A revealed score shows next to the teams** (e.g. "2–1", "1–1 a.e.t., 4–3 pens"). Watching a match doesn't reveal its score in the list; it only unlocks the first-leg score on the second-leg row, as decided.
- **D22. "Show original title…"** is in each row's right-click menu, behind a spoiler-warning confirmation. "Open on YouTube (may show score)" is the button on rows without an in-app highlight that have an official LALIGA video, and it's also in the right-click menu for every video.
- **D23. Manual Refresh obeys the 15-minute rule** as the plan says. The button's tooltip shows when data was last updated. Saving a new key forces a refresh.
- **D25. Window minimum 900×600.** Settings is the standard macOS Settings window (⌘,) with "API Keys" and "Advanced" tabs; first launch without a YouTube key shows a setup screen in the main window.
- **D26. Developer snapshot mode (Debug only):** `"Footy Highlights" --snapshot <dir> [--seed FootyKit/Tests/FootyKitTests/Fixtures] [--dark x]` renders the main screens to PNGs offscreen, using last season's fixtures, so UI checks never show current results. Used to verify M2–M4 without screen-recording permissions.
- **D27. README key steps now point to Settings** (with `.env` as the developer path), per the plan's note that the guides would move once the app exists.

### M3 — Player

- **D32. When the last video ends, the player is destroyed and a "Finished" panel shows** (Watch again / Back to round), after the player has been destroyed. Error panels: 101/150 "doesn't allow it to play inside other apps", 152/153 "YouTube refused…", 100 "no longer available", plus "Open on YouTube (may show score)".
- **D33. Links clicked inside YouTube's player** (logo, title) open in the default browser instead of inside the app.
- **D34. The player screen header shows the neutral title**, "Match info by Footy Highlights · video from <channel> on YouTube" and "Show original title…" (behind a spoiler confirmation), for ToS attribution (DP III.F.2.a). "Mark watched / Mark unwatched" is in the toolbar.
- **Verified 2026-10-12 (muted, offscreen, no screenshots of video):** NBC, CBS, beIN, USA Sports and ESPN FC videos all play in the app's WKWebView. Pause, resume and destroy-on-end work. An official LALIGA video returns error 150 and shows the error panel. **Not verified by me:** the in-player spoiler surfaces from the spike (title flash, hover, outro), which need eyes on a real screen. Please re-check those when you first watch something.

### M4 — League table
- **D35. Table columns:** #, Team, P, W, D, L, GD, Pts. No form, no goals for/against. The header reads "Table before <round>" plus how many revealed results from this round are included.
- **D36. Tiebreakers implemented** (head-to-head computed among the tied teams):
  - Premier League: points, GD, goals for, head-to-head points, head-to-head away goals.
  - La Liga and Serie A: points, then head-to-head points and GD **only once the tied teams have played each other twice**; otherwise GD, then goals for.
  - Bundesliga: points, GD, goals for, head-to-head, away goals.
  - Ligue 1: points, GD, head-to-head points / GD / goals, goals for.
  - UCL league phase: points, GD, goals for, away goals, wins, away wins.
  - Final fallback everywhere: alphabetical. UEFA's later criteria (opponents' points, disciplinary) and fair-play rules aren't modelled.
- **D37. Hovering a match highlights both teams' rows and scrolls the table to them** (useful for the 36-team UCL table).
- **D38. Only results revealed *in this round* are applied** to its table. Results revealed in later rounds don't leak backwards.
- Verified: the computed table for Premier League 2025-26 before Matchweek 11 matches football-data's official table exactly (unit test). Snapshot check with last season's data: reveal → table update, hover highlight, UCL/Carabao full-width rounds, light and dark mode.

### Changes requested 2026-10-12 (YouTube controls, queue, table in player)
- **D39. Superseded by your decision:** the app's own controls bar and duration hiding inside the player are gone (old D29–D31 removed). YouTube's controls handle play/pause, seeking, subtitles (C key or the CC button), quality, speed, full screen and keyboard. `iv_load_policy=3` keeps annotations off.
- **D40. Queue buttons:** each playable row has a "Queue" / "Queued" toggle next to Play (also in the right-click menu). A "Queue (N)" toolbar button on every browsing screen opens the queue popover: numbered list, drag to reorder, ✕ to remove one, **Clear Queue**, **Start Queue**. The popover shows the total length unless durations are hidden.
- **D41. Queue behaviour:**
  - The queue only holds upcoming videos. Each item leaves the queue and is marked watched the moment the player reaches it.
  - Videos play back-to-back in the same YouTube player, so full screen survives between videos.
  - The player screen's bottom bar shows "Up next", "+N more", the queue button and **Next** (skip). Starting the queue again doesn't re-add anything.
  - **The queue is saved between launches**; you didn't say either way.
  - Duplicates are ignored. Matches without an in-app highlight can't be queued.
- **D42. "Queue all unwatched"** is on every round panel (rounds screen) and in the round screen's toolbar. It appends the round's unwatched highlights in list order, skipping any already queued. Round rows are now guaranteed chronological (unmatched videos used to be appended at the end).
- **D43. "Show table" in the player:** a button in the bar below the video (⌘T) opens the round's pre-round table on the right, with the current match's two teams highlighted, and closes with ✕ or ⌘T. It only appears when the match's round has a table, not for cups or knockouts. It sits beside the video, so it isn't visible inside YouTube's own full screen. Use the window's green full-screen button instead to keep the table next to the video.
- Verified 2026-10-12: queue unit tests (not watched until reached; reorder; remove; clear). The muted headless player test shows all five channels play with YouTube's controls, and the queue hand-off works: video ends → next loads in the same player → plays → last one is destroyed. Queue popover and round panels checked by snapshot.
